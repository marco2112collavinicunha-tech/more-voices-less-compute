# More Voices, Less Compute

Repository: https://github.com/marco2112collavinicunha-tech/more-voices-less-compute

**Speech recognition for people who are hard to understand, compared by accuracy and carbon footprint.**


- The report is submitted separately; this repository holds the code, configuration and result files its numbers are generated from.
- Every number in the report is generated by code from the files in [`results/`](results/) — see [Traceability](#traceability).
- Every change to the analysis plan after it was fixed is dated in [`results/DEVIATIONS.md`](results/DEVIATIONS.md).

## The question

People whose speech is hard to understand (after a stroke, with cerebral palsy, Parkinson's disease or ALS, with developmental speech disorders) are the people speech recognisers serve worst. The usual remedies spend computation: a larger general-purpose recogniser, or a model retrained for each person. This study compares, on identical recordings, how much accuracy each approach delivers per unit of computation, energy and carbon. Validation uses the public TORGO corpus (speakers with dysarthria and control speakers).

| Approach | What is computed |
|---|---|
| A. General-purpose recogniser (Whisper-medium, zero-shot, forced choice among the speaker's words) | 30 s of padded audio + text decoder, for every word |
| B. Per-user retraining (4 variants of XLSR-53 fine-tuning) | a training run per user, then the full model per word |
| C. Frozen XLSR-53 **truncated at layer 12** + small classifier trained on **other people's recordings of the same words** | half the model per word; no training per user |

## Main results (TORGO, speakers with dysarthria unless stated)

| | Approach C (shared classifier) | Whisper-medium (forced choice) |
|---|---|---|
| Unweighted average recall, dysarthria | **80.5%** | 75.3% |
| Unweighted average recall, controls | 89.4% | **91.8%** |
| Computation per recognition | 1× | about 34× |
| Estimated energy per 2.2-s message (low-cost ARM board) | 13 J | 343 J |
| Estimated energy per user-year (100 messages/day) | 132 Wh (14.5 g CO₂e, Brazil) | 3,482 Wh |

- Stopping XLSR-53 at layer 12 gives identical output with 42% less computation, and layer 12 was more accurate than layer 24 for every speaker.
- About 16 recordings per word from other speakers matched Whisper-medium on average for speakers with dysarthria.
- At about the same computation as the shared classifier, Whisper-tiny reached 73.4% for speakers with dysarthria; Whisper-base reached 75.4%. With the word list given, Whisper's accuracy for these speakers did not grow with its size (it did for controls: 87.8%, 89.3%, 91.8%). Most of the saving over Whisper-medium comes from model size; at equal computation the examples added +7.1 points, not established with six speakers.
- Exploratory: the same shared classifier on Whisper-tiny's encoder reached 88.3% for speakers with dysarthria (91.1% controls) at 23 GFLOP per recognition, +14.9 points above Whisper-tiny's own forced choice (`pipeline/s08k_whisper_encoder_shared.py`).
- Exploratory: retraining the layer-12 model once on other speakers' recordings (a one-off cost shared by all users) reached 84.5% for speakers with dysarthria and 94.0% for controls at epoch 5 (`pipeline/s07b_shared_finetune.py`, `pipeline/s08l_shared_finetune_stats.py`).
- On recordings from a different session, the shared classifier kept 80.3%; a classifier using a single own recording per word fell to 17.9%.
- Per-user retraining cost up to 31 TFLOP per user (vs 0.56 TFLOP to embed the user's recordings) and, with one recording per word and settings fixed in advance, barely learned (retraining of the layer-12 model, 10 epochs: 38.9%).

Energy is **estimated** from counted operations with a published joules-per-operation figure; it was not metered (a metered run is scripted, see below). Six speakers per group, one laboratory, English single words: see the report's limitations section.

## Reproducing

1. Python ≥ 3.12; `pip install -r requirements.txt` (versions used: PyTorch 2.14, Transformers 5.x, scikit-learn, SciPy, pandas).
2. **Data.** TORGO is distributed by the University of Toronto for research use and is not redistributed here. Download the archives into `data/torgo/` from the corpus page (Rudzicz, Namasivayam & Wolff, 2012). Google Speech Commands v0.02 goes into `data/speech_commands_v0.02/`. Manifests in `data/manifests/` list the exact recordings used.
3. Run `make manifests embed classifiers whisper finetune stats` then `python -m pipeline.s08b_matched torgo` … `python -m pipeline.s08i_design torgo`, then `make report`. Model weights (`facebook/wav2vec2-large-xlsr-53`, `openai/whisper-*`) are fetched from Hugging Face on first use.
4. Without the audio, everything downstream of the embeddings and Whisper outputs can be re-run from `results/`: `python -m pipeline.s09_accuracy torgo && python -m pipeline.s09_report_assets && make report`, and `pytest -q`.

## Traceability

The report contains no hand-typed results. `pipeline/s09_accuracy.py` and `pipeline/s09_report_assets.py` read `results/` and write `report/generated/numbers.tex` (one LaTeX macro per number); the report's text uses only those macros. `docs/numbers_trace.csv` lists every macro, its value and the report sections that use it. `tests/test_core.py` fails if the report uses a number that is not generated.

## Demo

```
python -m demo.live_demo torgo --speaker M04     # replays the report's test recordings of a speaker with dysarthria
python -m demo.live_demo mic                     # say: yes no up down left right on off stop go
```
The classifiers in `demo/*.npz` were trained only on other speakers' recordings (`tools/train_demo_classifiers.py`). For each word the demo prints the recognised word, its confidence, latency, the counted operations and the estimated energy, next to what Whisper-medium would need.
